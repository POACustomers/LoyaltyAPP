# تحديث تجربة العميل والعروض — Dina's Corner

## ما تغيّر

1. **الصفحة الرئيسية:** بانر العروض عريض، والصورة وحدها ظاهرة داخله بلا كتابة أو تفاصيل فوقها، مع إبقاء التنقل بين العروض.
2. **الكاتيجوري:** الأقسام تظهر مباشرة تحت بانر العروض، مع رابط للمنيو الكامل.
3. **النقاط:** نُقلت بطاقة النقاط إلى أسفل الأقسام وأصبح شكلها أكثر اختصارًا حتى لا تزاحم العروض والمنيو.
4. **شريط تنقل ثابت:** أضيفت روابط Home وMenu وOffers وOrders وLoyalty في صفحات العميل المسجّل، وبألوان الهوية الحالية المعتمدة من الثيم. صفحات تسجيل الدخول والتسجيل لا تعرض الشريط.
5. **تفاصيل العرض:** الضغط على صورة أي عرض يفتح نافذة تفاصيل فيها الصورة، والاسم والوصف وتاريخ الصلاحية عند توفره.
6. **الطلب من العرض:** يحاول التطبيق مطابقة اسم المنتج مع صنف نشط في المنيو. عند وجود تطابق واحد واضح يعرض سعر المنيو الحالي وزر Add to basket، ثم يحفظ الصنف في السلة وينقل العميل إلى سلة المشتريات.
7. **حماية من ربط صنف خاطئ:** لا يضيف التطبيق المنتج تلقائيًا إذا لم يجد تطابقًا مؤكدًا أو إذا كان الصنف/قسمه غير نشط؛ يظهر بدلًا من ذلك رابط لفتح المنيو.
8. **إدارة العروض:** تمت إضافة اقتراحات أسماء أصناف المنيو إلى حقل اسم المنتج في صفحة GM لمساعدة المسؤول في إدخال الاسم المطابق.
9. **التخزين المؤقت:** تم تحديث إصدار Service Worker لكسر الكاش القديم.

## شرط الربط بين العرض والصنف

في صفحة GM، اختر اسم الصنف نفسه كما يظهر في المنيو. يعتمد الربط الحالي على مطابقة الاسم، ولا يضيف عمودًا جديدًا إلى قاعدة البيانات.

## تنبيه بخصوص الخصومات

جدول `offers` الحالي لا يحتوي على حقل منظم لسعر العرض أو نسبة/قيمة الخصم، كما أن إجراء إنشاء الطلب الحالي يعيد حساب السعر من `menu_items`. لذلك هذا التحديث يفتح تفاصيل العرض ويضيف الصنف **بسعر المنيو الحالي**؛ لا يدّعي تطبيق خصم مالي لم يتم تعريفه والتحقق منه على الخادم. إذا كانت هناك عروض بأسعار مخفضة فعلية، فالخطوة التالية هي إضافة قاعدة خصم منظمة وربطها بحساب إجمالي الطلب في Supabase من جهة الخادم قبل عرض سعر مخفض للعميل.

## فحوصات ما قبل التسليم

- اجتازت ملفات JavaScript المنفصلة فحص الصياغة بـ Node.js.
- تم فحص 25 كتلة JavaScript داخل HTML ولم تظهر أخطاء صياغة.
- تم فحص 50 صفحة HTML ولم تظهر روابط/ملفات محلية مفقودة.
- لم يتم تعديل قاعدة بيانات Supabase أو تشغيل أي SQL، ولم يتم النشر على GitHub.
- لا يمكن تأكيد تطابق العروض الفعلية مع أصناف المنيو أو اختبار الطلب الحي قبل النشر وتسجيل الدخول بحساب العميل؛ يلزم اختبار ذلك على الموقع المنشور.

## رفع النسخة

1. فك ملف ZIP.
2. افتح مجلد `LoyaltyAPP-main` وارفع محتوياته إلى مستودع GitHub الحالي مع الحفاظ على بنية المجلدات، واستبدال الملفات القديمة بالنسخة الجديدة.
3. بعد النشر، افتح التطبيق على الهاتف وسجّل الدخول كعميل، ثم جرّب صورة عرض مرتبطًا باسم صنف موجود في المنيو. تأكد أن الصنف يظهر في السلة قبل تأكيد الطلب.
4. لا تشغّل ملفات bootstrap أو SQL القديمة؛ لا يوجد SQL مطلوب لهذا التحديث.
