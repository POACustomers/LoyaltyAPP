# قبل التشغيل التجريبي — POACustomers

## أ. إعداد هوية كل شركة
- POAC هي مالكة البرنامج فقط؛ اسم وشعار وألوان العميل تظهر في واجهته.
- نسخة Dina's Corner لها إعدادات مستقلة في `assets/tenant-config.js`، واتصال قاعدة بياناتها موجود في `assets/config.js`.
- لإضافة شركة أخرى، استخدم مجلد `POAC-Multi-Client-Kit/tenants/CLIENT_TEMPLATE`، أنشئ مشروع Supabase جديدًا، وضع بياناته وشعاره وألوانه في `tenant.json`، ثم ابنِ نسخة مستقلة بالأمر الموجود في دليل الـ Kit. لا تستخدم قاعدة بيانات دينا للعميل الجديد.

## ب. نظام الطلبات
1. افتح SQL Editor في قاعدة البيانات الخاصة بهذه الشركة، وشغّل `POACustomers-pickup-orders-setup.sql` بعد إعداد جداول المنيو والفروع.
2. بعد تشغيل SQL، افتح GM → Branch Locations، أضف الفروع ثم استخدم قسم **Assign Staff to Branches** لإسناد كل حساب Staff إلى فرعه. لا تحتاج لتعديل `profiles.location_id` يدويًا.
3. الطلبات التشغيلية تظهر لحساب Staff المسؤول عن الفرع فقط. GM لا يرى قائمة الطلبات ولا يستطيع تغيير حالتها؛ صلاحيات إسناد الموظفين منفصلة عن صلاحية تشغيل الطلبات.
4. العميل يختار Pickup أو Delivery. عند اختيار Delivery يجب إدخال العنوان الكامل وإرفاق GPS أو رابط Google Maps.
5. جرّب طلب استلام وطلب توصيل، وتأكد أن الموظف الصحيح فقط يشاهد الطلب، وأن العنوان ورابط الخريطة يظهران له.

## ج. شكل البرنامج الأساسي والعملاء المتعددون
- POAC هي الشركة المالكة للمنصة فقط. اسم وشعار وألوان العميل هي التي تظهر داخل واجهته.
- عند إضافة شركة جديدة، أنشئ لها مشروع Supabase مستقلًا، ثم أنشئ build مستقلًا من `POAC-Multi-Client-Kit` باستخدام إعدادات وشعار وألوان وملف قاعدة بيانات خاص بها. لا تستخدم قاعدة دينا لعميل آخر.
- الأوامر التشغيلية تظهر للـ Staff المعيّن للفرع فقط؛ الـ GM يدير الفروع والمنيو لكنه لا يدير طلبات العملاء.

## د. حدود ما تم التحقق منه
تم فحص ملفات JavaScript والـ HTML والأرشيف. لم يتم تشغيل SQL على قاعدة بيانات حيّة أو تنفيذ طلب حقيقي على الموقع المنشور؛ يجب اختبار ذلك على مشروع الشركة قبل استقبال عملاء فعليين.
