# إلزام سبب إلغاء الطلب — Dina's Corner

## الملفات المعدّلة
- `assets/pickup-orders.js`: يطلب سببًا غير فارغ من الموظف عند اختيار إلغاء الطلب، ويرسل السبب إلى RPC جديد، ويعرض السبب ضمن تفاصيل الطلب عند تحميله.
- `CANCELLATION-REASON-PATCH.sql`: يضيف عمودي سبب الإلغاء ووقت الإلغاء، وينشئ RPC يتحقق من المستخدم والفرع وحالة الطلب قبل حفظ الإلغاء.

## مهم قبل النشر
1. خذ نسخة احتياطية من قاعدة البيانات/المشروع.
2. راجع عمود `profiles.is_active` في مشروع Supabase. إذا كان اسم حقل تفعيل الحساب مختلفًا في قاعدة بياناتك، عدّل شرطه في SQL قبل التشغيل.
3. شغّل `CANCELLATION-REASON-PATCH.sql` في Supabase SQL Editor. لا تشغّله قبل مراجعة أسماء الأعمدة وصلاحيات الأدوار في مخططك.
4. انشر ملف `assets/pickup-orders.js` المحدّث مع الاحتفاظ بباقي ملفات المشروع كما هي.
5. اختبر بحساب Staff تجريبي: إلغاء مع سبب، إلغاء بسبب فارغ، محاولة إلغاء طلب تابع لفرع آخر، ومحاولة إلغاء طلب مكتمل.

لا يوجد اتصال بقاعدة Supabase الفعلية في بيئة إعداد الملف، لذلك لم يمكن اختبار SQL على قاعدة المشروع الحية. لا تعتبر الميزة جاهزة للإنتاج حتى تنجح اختبارات Supabase أعلاه.
